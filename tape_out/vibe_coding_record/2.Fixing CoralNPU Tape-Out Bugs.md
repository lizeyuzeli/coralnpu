# 1. `AsyncFIFOFwft` 只能跑半带宽

## 现状分析
`@/home/lizeyu/eng/coralnpu/tape_out/hdl/chisel/src/coralnpu/LvdsLink.scala:168-193` 的状态机：
- 一次 pop 流程：cycle N 拉 `rd_en`→ cycle N+1 拿 `rd_data` 写入 `buf`、清 `popPending` → cycle N+2 才能再次 `rd_en`。
- `canPop = bufWillBeEmpty && !empty && !popPending`，`popPending` 在被采样的那一拍已经为 1，挡住了下一拍的 `rd_en`。

所以即便下游 `deq.ready` 一直为 1，**每 2 个核心周期才能出一拍**，恰好是半带宽。这点是设计预期写的（注释里也提到了），但你说的没错，**是可以做到全带宽的**。

## 全带宽方案（建议）
把单 entry 的 `buf` 升级成 **2-entry skid（深度=2）**，配合"提前发射 `rd_en`"：
- 维护 `count ∈ {0,1,2}`（已经在 skid 中的 entry 数），以及 1-bit `popPending`（这一拍 `rd_en` 已发，下拍数据要落地）。
- 只要 `count + popPending < 2` 且 `!empty`，就拉 `rd_en`。这样上一拍发了 `rd_en`、下一拍可以**继续发** `rd_en`，因为 skid 还有空位接收即将到来的旧数据。
- 当下游 `deq.fire`，从 skid 头部弹出，count--。
- 当 `popPending` 那一拍数据返回，写入 skid 尾部，count++。

这样稳态下 `rd_en` 可以每拍都拉高 → 1 beat/cycle，全带宽。读侧增加约 128b×1 个寄存器 + 一些控制逻辑，开销很小。

如果你确认了，我把 `AsyncFIFOFwft` 改成这个 2-deep skid 实现（接口不变，调用处 0 改动）。

# 2. `dmi_jtag` 的引入是否合理 / 为什么多一个 wrapper 和 `prim_assert`

## wrapper 是必要的（合理）
FPGA 那边 `@/home/lizeyu/eng/coralnpu/fpga/rtl/chip_nexus.sv:349-367` 是 SV，可以直接用 `dm::dmi_req_t` / `dm::dmi_resp_t` 这种 packed struct。但 Chisel 的 `BlackBox` 没有办法直接连 SV package 类型的端口；如果直连会让 Chisel 侧不得不引入 `dm_pkg` 的 Scala 表示。

`@/home/lizeyu/eng/coralnpu/tape_out/hdl/verilog/dmi_jtag_wrapper.sv:30-90` 的作用就是把 struct 拍平成 `logic [31:0]/[1:0]`，让 Chisel 侧用纯 `UInt` 接，**这是惯用做法**，结构上和 fpga 端是等价的（只是端口形式不同）。

## [prim_assert.sv](file:///home/lizeyu/eng/coralnpu/tape_out/hdl/verilog/prim_assert.sv:0:0-0:0) shim 的来由
`@/home/lizeyu/eng/coralnpu/tape_out/hdl/verilog/prim_assert.sv:14-29` 注释解释得很清楚：
- `pulp_riscv_dbg` 和 `prim_*` cells 的源代码 ``include `"prim_assert.sv"``，而上游的 [prim_assert.sv](file:///home/lizeyu/eng/coralnpu/tape_out/hdl/verilog/prim_assert.sv:0:0-0:0) 又 chain include 多个 `.svh`（`prim_assert_dummy_macros.svh`、`prim_flop_macros.sv` 等）。
- FPGA 端走 fusesoc，会自动把这些 `.svh` 拷到 sandbox。**而我们这里走的是 bazel `rules_hdl` 的 `verilog_library`，它不会传播 `.svh` 到 verilator sandbox**。
- 所以加了一个 no-op 的本地 shim，把所有 assertion 宏定义成空，仿真行为与 verilator 模式下的上游 dummy macros 完全等价。

**结论**：wrapper 合理且不可避免；[prim_assert.sv](file:///home/lizeyu/eng/coralnpu/tape_out/hdl/verilog/prim_assert.sv:0:0-0:0) shim 是 bazel build system 限制的产物，不是逻辑差异。两者都建议保留。

> 唯一的可选优化：如果你希望流片端 RTL 与 fpga 完全字节级一致，可以改 bazel 规则把上游 `.svh` 加到 `verilog_library` 的 `data` 里，从而**不再需要 shim**。但这要动 BUILD 规则，对仿真行为没有任何区别，性价比不高。我的建议是**不动**。

### H1：背靠背 deq 时 credit 会丢

## 根因总结

**Bug 在 `LvdsTxArbiter.rrPtr` 的回绕逻辑**：

```scala
// BUG (旧)

```

`numSources=3`，`rrPtr` 是 `log2Ceil(3)=2` bit 寄存器。当 `sel=2` 时，`sel+1=3` 写回去就保留 0b11=3（**越界**，合法值应为 0..2）。

`.extdata`（filter_data, bias_data, scratch_buf）位于 EXTMEM = 0x20000000+，访问路径：

`Core.io.ebus` → `CoreChipKernel.io.ebus` → `LvdsAdapterChip.LvdsEBusShim` → LVDS link → `LvdsAdapterFpga.LvdsFpgaEBusAgent` → `ebus2axi` (DBus2Axi) → `io.axi_master` → 外部 verilator AXI memory

## 已诊断结论

**slave path 写 extdata 应该是对的**（python load_elf 后两个 run 看到相同的 extdata；如果写错两个 run 都会读到同样的脏值，结果会一致）。所以 bug 在 ebus master path（`LvdsEBusShim` ↔ `LvdsFpgaEBusAgent` ↔ `ebus2axi`）。

# 总结

## Bug 根因

[LvdsAdapterFpga.scala](file:///home/lizeyu/eng/coralnpu/tape_out/hdl/chisel/src/coralnpu/LvdsAdapterFpga.scala:0:0-0:0) 里 `LvdsFpgaEBusAgent.sDriveBus` 在 `dbus.ready` 拉高的**同一拍**就把 `dbus.rdata` 锁进 `rdataReg`。但 [DBus2Axi.scala](file:///home/lizeyu/eng/coralnpu/hdl/chisel/src/coralnpu/DBus2Axi.scala:0:0-0:0) 的 `readNext`（注释显式写了 *"Insert delay register to match dbus interface expecations, changing on fire"*）让 `dbus.rdata` **延后一拍**才反映本笔事务的数据 —— 同一拍上看到的是上一笔事务的值。

后果：每一笔 `extdata` master 读返回的都是上一笔的数据。在我加的 diagnostic 里，scalar 全部归 0、vector 整体 off-by-16 beat、scratch round-trip shifted by 16；端到端表现就是 conv2d 的 RVV [run_opt](file:///home/lizeyu/eng/coralnpu/tape_out/tests/cocotb/tutorial/tfmicro/conv2d_test.cc:119:0-127:1) 用错的 filter / scratch 值算累加 → 输出全饱和到 ±127。

## 修复

`@/home/lizeyu/eng/coralnpu/tape_out/hdl/chisel/src/coralnpu/LvdsAdapterFpga.scala:301-313` 加了 `sLatchRdata` 中间态：read 在 `dbus.ready` 拉高后先转到这个 state 等一拍，让 DBus2Axi 的 `readNext` 寄存器更新到位再采样；write 没 rdata 直接跳 `sSendRsp`。修改聚焦只一处。
