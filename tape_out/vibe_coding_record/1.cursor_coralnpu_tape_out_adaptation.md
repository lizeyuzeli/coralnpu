## 0. 关键背景信息（确认一下）

- 目前 tape-out 用的核 `lsuDataBits = 128`（看 BUILD 里 `RvvCoreMiniAxi`/`CoreMiniAxi` 都是 `--lsuDataBits=128`），所以 `axi2DataBits = 128`，`axi2AddrBits = 32`，`axi2IdBits = 6`。**LVDS 的 128bit 正好对得上 fabric / AXI 数据宽度**，下面所有打包都是按 1 拍命令 + 1 拍 data 设计。
- `CoreAxi` 内部结构本来就是：
  - **slave 路径**：`io.axi_slave` → `axiSlave`(AXI→FabricIO) → `fabricMux` → ITCM/DTCM/CSR
  - **master 路径**：`core.io.ibus` / `core.io.ebus.dbus` → `ibus2axi` / `ebus2axi` → `io.axi_master`
- 你给的 `AsyncFIFO_RTL` + `Block_DualPort_RAM` 是 std-mode 异步 FIFO。

所以 LVDS 适配可以直接"插"在 fabric / ibus / dbus 这一层，不需要在流片侧承载 AXI。

## 2. LVDS 包格式（128bit 一拍）

LVDS Tx / Rx 都是 128-bit。我用最朴素的设计：**一笔事务 = 1 拍 header + 0/1 拍 data**。

### Header 拍（128bit）
| 字段 | 位宽 | 含义 |
|---|---|---|
| opcode | 4 | 见下表 |
| id | 8 | 区分事务源（ibus=1, ebus=0, slave 用 axi id 截断 6→6 位） |
| addr | 32 | 地址 |
| strb | 16 | byte strobe（128bit→16） |
| size | 3 | axi size（写时来自 dbus.size 编码） |
| flags | 4 | last/burst 等 |
| reserved | 61 | |

### Data 拍（128bit）
- 直接放 128-bit 数据（写数据 / 读返回数据）。

### Opcode（chip→FPGA Tx）
| opcode | 含义 | 是否带 data 拍 |
|---|---|---|
| `S_RD_RSP_OK` | slave 读响应数据 | 是 |
| `S_RD_RSP_ERR` | slave 读响应失败 | 否 |
| `S_WR_RSP` | slave 写响应（status 在 header） | 否 |
| `M_IBUS_REQ` | ibus 读请求 | 否 |
| `M_DBUS_RD_REQ` | dbus/ebus 读请求 | 否 |
| `M_DBUS_WR_REQ` | dbus/ebus 写请求 | 是 |

### Opcode（FPGA→chip Rx）
| opcode | 含义 | 是否带 data 拍 |
|---|---|---|
| `S_RD_REQ` | slave 读请求（fabric.readDataAddr） | 否 |
| `S_WR_REQ` | slave 写请求（fabric.writeDataAddr+strb+data） | 是 |
| `M_IBUS_RSP` | ibus 读返回 | 是 |
| `M_DBUS_RD_RSP` | dbus 读返回（含 resp） | 是 |
| `M_DBUS_WR_RSP` | dbus 写返回（status 在 header） | 否 |

> 注：在 chip 内 fabricMux 接的是 `FabricIO`，所以 chip 这边把 LVDS 解出来直接拼成一个 `FabricIO` 给 fabricMux；FPGA 那侧反过来——拿 `FabricIO` 接 `AxiSlave`，再把 `AxiSlave.io.axi` 暴露成 axi_slave。这样**完整 AXI 协议就只在 FPGA 侧承载**，与你的要求一致。
>
> ibus/dbus 同理：chip 侧**不实例化 IBus2Axi/DBus2Axi**，而是直接把 core 的 ibus/ebus 接到 LVDS 适配器；FPGA 侧用 `IBus2Axi`/`DBus2Axi` 还原成 axi_master。

## 3. 异步 FIFO 跨时钟域

- 用你给的 `AsyncFIFO_RTL`（包成 Chisel BlackBox），数据宽度 = 128 + opcode 几位（或者直接 132~144bit）。
- 两条：
  - `tx_fifo`：写入 = core_clk（pack 出来的帧），读出 = lvds_clk（喂给 LVDS Tx）。
  - `rx_fifo`：写入 = lvds_clk（LVDS Rx 直接灌），读出 = core_clk（unpack 后送回 fabric/ibus/dbus）。
- 两边 reset 用各自时钟域的同步释放（`RstSync` 已经有了，复用它）。

## 4. Credit 流控（GPIO）

LVDS Rx 没有 ready，所以做 **credit return**：

- **chip→FPGA 方向**（FPGA 是接收方，没 ready）：FPGA 端的 rx_fifo 每弹出一项就在 GPIO 上给 chip 发一个 credit pulse，chip 端 Tx 看到 credit++ 才允许发。
- **FPGA→chip 方向**（chip 是接收方，没 ready）：chip 端的 rx_fifo 每弹出一项就在 GPIO 上给 FPGA 发一个 credit pulse。

> 你说"单独加一个 gpio 用于做 credit 流控的 update 更新信号"——需要确认是**只一个方向**还是**两边各一个**。物理上看一对 LVDS Rx/Tx 双方都没 ready 的话，**两边各需要一个 credit GPIO**（因为各方向都要单独 credit）。我的方案默认两条 credit 线（一进一出），如果你只想做一根，告诉我哪个方向（见"待你确认"）。

- 初始 credit = rx_fifo 深度。reset 释放后 chip/FPGA 互相清楚对方深度即可（用编译期参数）。
- credit pulse 跨时钟域：用一个 toggle 或 2-flop 同步 + 边沿检测。

### B. LVDS 包格式（128bit/拍）

### C. 异步 FIFO
直接 BlackBox 包你写的 `AsyncFIFO_RTL`，深度先按 8（ADDR_WIDTH=3）来；DATA_WIDTH = 128（payload 拍）+ opcode 几位。具体是分 header/data 两个独立 FIFO 还是统一一个 FIFO 带 type bit，我打算**统一一个 FIFO**，每个 entry 132~144bit，简单清晰。

### D. Credit 流控（**默认 2 根 GPIO**）
- `credit_to_fpga` (output): 流片每弹出一个 Rx FIFO entry 就 pulse 一拍。FPGA 端 Tx 凭 credit 计数发送。
- `credit_from_fpga` (input): 反向同理。
- 跨 lvds_clk / core_clk 用 toggle + 2-flop 同步 + 边沿检测 → 累加到 credit 计数器。
- 初始 credit = FIFO 深度（编译期常量两边对齐）。

### E. boot_addr & lvds_clk（**编译期参数**）
- `Core_Axis(p, bootAddr: BigInt = 0x10000000L, ...)`：boot_addr 内部硬接 `bootAddr.U(32.W)` 给 csr。
- `Core_Axi_Axis` 同样接受这个参数（默认 0x10000000）。
- 验证里 lvds_clk 默认与 aclk 同源（同一时钟），异步 FIFO 在同步时钟下也能跑（Gray 码同步退化为透传）；如果你后面想做异步抖动测试，verilog testbench 里另外接一个独立时钟即可。

## 2. `wready` timeout：根因与修复

**根因**：`CoreChipKernel` 里 fabric/TCM/`AxiSlave` 等价物都在 **`RstSync` 输出的门控时钟 `clk_o`** 上（与 `CoreAxi` 里 `AxiSlave` 一致），而 **`LvdsAdapterChip` 的 `core_clk` 却接在裸 `aclk` 上**。`fabricSlave` 与 `fabricMux` 之间是直接连线，相当于 **两个不同时钟域在硬连 fabric 握手**，仿真上常见表现就是 **slave 写通道 `wready` 长期不对应**。

**修改**：

- **`CoreChipKernel`**：增加 `gated_clk`、`adapter_aresetn` 输出；`gated_clk := rst_sync.io.clk_o`，`adapter_aresetn` 与内部 `global_reset` 用的 te/RstSync 选择一致。
- **`Core_Chip`**：`LvdsAdapterChip` 的 `core_clk` / `core_aresetn` 改为 **`kernel.io.gated_clk` / `kernel.io.adapter_aresetn`**；**`dmi_jtag`** 也改用同一时钟/复位，与 DM 同域。
- **`Core_Axi_Chip`**：`fpga.io.core_aresetn := chip.io.core_sync_aresetn`，避免 **FPGA 已出复位、片上网侧 LVDS 仍在 RstSync** 时先行发帧导致 credit/环回不匹配。
- **`Core_Chip`** 顶部端口增加 `core_gated_clk`、`core_sync_aresetn`（给验证/顶层观测用；`Core_Axi_Chip` 里已用 `core_sync_aresetn`）。
- **`Core_Chip`**：`dm.req.bits.op` 改为 **`DmReqOp.safe(...)`**，去掉你日志里那条 `DmReqOp` cast 告警。
