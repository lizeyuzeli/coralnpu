# TFLite-Micro End-to-End Model Tests (ST AI-Zoo)

Each subdirectory here corresponds to one INT8-quantized model from the
[ST AI-Zoo](https://github.com/STMicroelectronics/stm32ai-modelzoo) and
ships an **end-to-end cocotb test**: the model is flashed into
RvvCoreMini's memory, a real reference input is fed through `Invoke()`,
and the output is read back and compared against a golden produced by
the TFLite reference interpreter (BUILTIN_REF, i.e. no XNNPACK delegate
rewriting).

The directory mirrors the conventions of `../arm_ml_zoo/` (same
`run_<model>.cc` + `cocotb_<model>.py` + `BUILD` triplet, same
`tags = ["manual"]` policy, same `RvvCoreMiniHighmemAxi` toplevel). See
that directory's `README.md` for the full template / authoring guide;
this file only documents what is specific to the ST AI-Zoo set.

## 2. What's different from `arm_ml_zoo/`

The Arm ML-Zoo ships int8-in / int8-out models with reference
`input_0.npy` / `expected_output_0.npy` already provided. ST AI-Zoo
models on the other hand are typically:

1. **uint8-in / float32-out** -- the trailing `DEQUANTIZE` returns
   probabilities directly, which means the host-side comparison happens
   in float32 with a small absolute-difference tolerance instead of the
   `<= 1` LSB int8 rule used in `arm_ml_zoo/`.
2. **Distributed without a canonical reference I/O pair.** Each
   subdirectory therefore has a `prep_test_data.py` that:
   - loads `images/example.jpg`,
   - center-crops + resizes to the model's input shape,
   - runs the BUILTIN_REF TFLite interpreter to produce a deterministic
     golden,
   - writes `test_data/input_0.npy` and `test_data/expected_output_0.npy`.

   `BUILTIN_REF` opt-out is critical: TFLite's default XNNPACK delegate
   silently rewrites a few int8 ops to FP/AVX equivalents and adds
   sub-LSB rounding noise that the on-device TFLM reference path will
   not match.

3. **Some models contain dynamic-shape tail ops** (`SHAPE`,
   `STRIDED_SLICE`, `PACK`, `RESHAPE`) that the ST converter emits
   around the post-pool reshape. These have to be added to the
   `MicroMutableOpResolver` on the device side; otherwise the TFLite
   converter's "DELEGATE" placeholders make the host-side argmax look
   right while the device side fails to register the op.

### Per-subdirectory file set

```
<model_name>/
  BUILD
  prep_test_data.py                        # one-shot golden generator
  run_<model_name>.cc                      # device runner (clean inference)
  cocotb_<model_name>.py                   # host-side test (argmax + tolerance)
  run_<model_name>_per_op_cycles.cc        # device runner with MicroProfiler
  cocotb_<model_name>_per_op_cycles.py     # host-side per-op CSV emitter
  models/<model>.tflite
  models/<model>_config.yaml
  images/example.jpg
  test_data/input_0.npy                    # generated by prep_test_data.py
  test_data/expected_output_0.npy          # generated by prep_test_data.py
```

`mobilenetv1_a025_224_int8/` and `miniresnetv1_s1_64x50_tl_int8/` are
the int8-in / int8-out outliers (no QUANTIZE/DEQUANTIZE wrappers), so
their prep scripts and runners follow the int8 rule directly.

## 3. Two test variants per model

Every subdirectory exports two cocotb suites:

### 3.1 `cocotb_<model>` -- end-to-end correctness

Drives one inference, reads back the float32 (or int8) output tensor,
and asserts:

- `inference_status == 0` (i.e. `Invoke()` returned `kTfLiteOk`),
- `argmax` matches the golden,
- `max(|actual - expected|) <= _MAX_ABS_DIFF` (typically `3e-2` for
  softmax outputs, since the trailing DEQUANTIZE LSB is `~ 1/256`;
  int8-out models use `<= 1` LSB instead).

### 3.2 `cocotb_<model>_per_op_cycles` -- per-layer profiling

Wires a custom `tflite::MicroProfilerInterface` into `MicroInterpreter`
that snapshots `mcycle` around every op invocation. After the run, the
host reads back three globals:

- `op_profile_count` -- number of recorded ops,
- `op_profile_cycles[64]` -- per-op cycle deltas,
- `op_profile_tags[64 * 24]` -- the human-readable op tag for each slot
  (e.g. `CONV_2D`, `DEPTHWISE_CONV_2D`, `SOFTMAX`).

The host emits a CSV at
`$TEST_UNDECLARED_OUTPUTS_DIR/op_cycles.csv`, which under `bazel test`
ends up as a regular test artefact in
`bazel-testlogs/<package>/<target>/test.outputs/`. Columns:

| idx | op_name | cycles | time_ns |
|---|---|---|---|
| 0 | QUANTIZE              | ... | ... |
| 1 | CONV_2D               | ... | ... |
| ... |                     |     |     |
|     | TOTAL_PROFILED       | ... | ... |
|     | TOTAL_INVOKE_WALL    | ... | ... |

The pass criteria are intentionally weak (inference succeeds, sum of
profiled cycles is non-zero) so that this target doubles as a
profiling tool rather than a regression on absolute cycle counts.

## 4. How to run

```bash
# 1) Regenerate the golden if the model or example image changed.
python3 tests/cocotb/tflite/st_ai_zoo/<model>/prep_test_data.py

# 2) Build only (sanity-check ELF + cocotb runner).
bazel build //tests/cocotb/tflite/st_ai_zoo/<model>:all

# 3) End-to-end correctness.
bazel test \
  //tests/cocotb/tflite/st_ai_zoo/<model>:cocotb_<model>_core_mini_rvv_<model> \
  --test_output=streamed --test_timeout=4200

# 4) Per-op cycle profiling -> CSV in bazel-testlogs/.../test.outputs/.
bazel test \
  //tests/cocotb/tflite/st_ai_zoo/<model>:cocotb_<model>_per_op_cycles_core_mini_rvv_<model>_per_op_cycles \
  --test_output=streamed --test_timeout=4200
```

All targets are `tags = ["manual"]`, so a bare
`bazel test //tests/cocotb/tflite/st_ai_zoo/...` will not trigger
anything; targets must be enumerated explicitly (or wrapped in a
profile-style runner).

## 5. Adding a new ST AI-Zoo model

1. Drop `<new_model>/models/<model>.tflite` plus `images/example.jpg`
   (or whatever input fits the model's modality).
2. Inspect the op inventory with `BUILTIN_REF`:
   ```python
   import tensorflow as tf
   i = tf.lite.Interpreter(
       model_path="<model>.tflite",
       experimental_op_resolver_type=tf.lite.experimental.OpResolverType.BUILTIN_REF,
   )
   i.allocate_tensors()
   for op in i._get_ops_details(): print(op["op_name"])
   ```
   If `XNNPACK` rewrites are visible (`DELEGATE` entries in the default
   resolver), pin to `BUILTIN_REF` everywhere -- both in
   `prep_test_data.py` and conceptually on-device.
3. Copy the closest existing subdirectory as a template (rule of thumb:
   FP-output classifier with QUANTIZE/DEQUANTIZE wrappers ->
   `mobilenetv1_a025_96_fft_int8_tf_flowers/`; FP-output ResNet with
   skip connections -> `resnet8_32_tfs_int8_cifar10/`; tiny FP-output
   classifier -> `st_mnistv1_28_tfs_int8_emnist_byclass/`; pure int8-in
   / int8-out -> `miniresnetv1_s1_64x50_tl_int8/`).
4. Update `BUILD`, `prep_test_data.py`, the two `run_*.cc` runners, and
   the two `cocotb_*.py` host tests with the new shapes, op registrations,
   and `MicroMutableOpResolver<N>`.
5. Run `prep_test_data.py` to materialize `test_data/*.npy`, then
   `bazel build //...:all` to sanity-check the ELFs, and finally the
   two `bazel test` invocations from section 4.
